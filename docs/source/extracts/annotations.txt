FORM OUTPUT DATA.DOCX — FLOATING SHAPE ANNOTATIONS
==================================================

19 anchored text-box shapes drawn ON TOP of the 17 embedded screenshots.

These are NOT paragraph text. They live in <mc:AlternateContent><wps:txbx> shapes
with <wp:anchor> positioning, and a naive text extraction returns them as loose
sentences with no indication of which image — or which part of which image —
they belong to. The positions below were recovered from the anchor offsets and
are what make them readable.

Anchor frame: positionV is relativeFrom="paragraph", and each image sits alone in
its paragraph, so **y is measured from the top edge of the image**. positionH is
column / margin / page; page-relative values have the 1" page margin subtracted
below so every x is relative to the image's left edge.

REPRODUCING
-----------
Shapes are in word/document.xml. Take the mc:Choice branch only — mc:Fallback
holds a VML duplicate of every shape and will double every annotation.

    import xml.etree.ElementTree as ET
    MC = 'http://schemas.openxmlformats.org/markup-compatibility/2006'
    WP = 'http://schemas.openxmlformats.org/drawingml/2006/wordprocessingDrawing'
    W  = 'http://schemas.openxmlformats.org/wordprocessingml/2006/main'

    for alt in root.iter(f'{{{MC}}}AlternateContent'):
        ch = alt.find(f'{{{MC}}}Choice')          # never iterate the whole alt
        anchor = ch.find(f'.//{{{WP}}}anchor')
        text = ''.join(n.text or '' for n in ch.iter(f'{{{W}}}t'))
        # anchor/positionV/posOffset is EMU; /914400 = inches from image top

To render them back over the screenshots, note each image carries an <a:srcRect>
crop (l/t/r/b as parts-per-100000) that removes the PDF-viewer chrome. Apply the
crop first, then scale by (cropped_pixels / displayed_inches) from <wp:extent>.
